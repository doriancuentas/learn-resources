Deployment hierarchy

The same service code runs through different identity paths in production and development.

Production

  • Internet → ingress-pinadmin → Helix pod
  • Helix pod → mesh mTLS → MCP pod + Envoy
  • MCP pod → mesh mTLS → token-broker pod + Envoy + Knox
  • token_broker → MySQL token store and Snowflake OAuth endpoints
  • MCP → Snowflake warehouse with the user's OAuth token

Current two-devapp layout

  • Helix-test → devapp 2 mcp-* host → MCP on port 8000
  • MCP → devapp 1 mcp-* SSO host → broker on port 8000
  • Browser → the same broker SSO host → X-Forwarded-User
  • Broker → SQLite and an in-memory development encryption key
  • Both services → Snowflake development account over HTTPS
